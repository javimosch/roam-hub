# M0 — the loop, end to end

**Goal:** one autonomous run travels the full circuit: spec → trigger → worker
poll → metered LLM proxy → journal → done → peage charge → webhook report.
**Dogfood:** the rbm21 sentinel (nightly read-only health check, report → WhatsApp bridge).

## Slices

1. **Store + HTTP shell** — SQLite schema (tenants/agents/runs/events), signup +
   bearer auth, `/_health`, `/v1/guide`, `llms.txt`. `src/db.src`,
   `src/server.src`, `src/handlers_agents.src`.
2. **Agent CRUD + trigger tick** — `POST /v1/agents` (spec: name, prompt, model,
   every_secs, budget_microeur, report_url), pause/resume; a `go`-routine tick
   that queues a run when an agent is due. `src/trigger.src`.
3. **Worker protocol** — `GET /v1/work` (long-poll-ish: returns a queued run or
   204), `POST /v1/run/events`, `POST /v1/run/done`. Worker auth = per-tenant
   worker token. `src/handlers_runs.src`.
4. **Metered LLM proxy** — `POST /v1/llm`: forward to Anthropic/OpenRouter with
   platform key, count tokens from the response, accumulate run cost, refuse
   (typed error `budget_exhausted`, recoverable:false) once budget is spent.
   `src/proxy.src`.
5. **Billing** — on run done: peage merchant charge `cost × 1.3 + 1¢`,
   idempotency key = run id. Solvency check before queueing a run.
   `src/billing.src` (idiom: grepapi `billing.src`).
6. **Report-out** — webhook POST with run summary + journal tail; one attempt,
   typed failure recorded in journal (no internal retries — bible rule).
   `src/report.src`.
7. **roam `--worker` mode** — PR against ~/ai/roam: poll hub, execute spec with
   the existing engine (sandbox, goal-verify), stream events, report done.
   Separate repo, separate PR.
8. **`maa` CLI** — thin client: signup, agent create/list/pause, runs list,
   journal tail. Bible-compliant (--json default-on, semantic exit codes).
   `cli/`.
9. **Deploy + dogfood** — hotify to agents.intrane.fr, register rbm21's roam as
   worker, create the sentinel spec, watch one real nightly run bill and report.

## Non-goals (M0)

Full cron syntax (interval only) · webhook-in triggers · multi-worker routing ·
side-effecting runs (Report rung only) · any UI.
